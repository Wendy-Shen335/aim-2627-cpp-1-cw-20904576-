## 0 一句话结论

题目要的是：**把每条记录分进「首次合法 / 合法重复 / 非法」三类之一，首次合法记录把血量夹到 [0,100] 后累加，最后按编号升序返回所有合法编号。**

分类顺序不能乱：

> **先验范围 → 再判重复 → 最后计入首次合法**

非法记录**不占编号**，所以一个 id 先出现非法、后补发合法时，后者仍是首次合法；反过来，已见编号的记录即使血量非法，也要计 `invalid` 而不是 `duplicate`。

## 2 接口与数据含义

```cpp
struct Telemetry { int id; int hp; };
struct Summary { int valid; int duplicate; int invalid; long long total_hp; std::vector<int> ids; };
Summary summarize(const std::vector<Telemetry>& frames);
```

| 名称 | 类型 | 题面保证 | 含义 |
| --- | --- | --- | --- |
| `frames` | `const std::vector<Telemetry>&` | 最多 20000 条；字段可为任意 `int` | 输入记录，**不可修改** |
| `valid` | `int` | ≥ 0 | 首次合法记录数 |
| `duplicate` | `int` | ≥ 0 | 合法但编号已出现的记录数 |
| `invalid` | `int` | ≥ 0 | 范围非法的记录数 |
| `total_hp` | `long long` | — | 首次合法记录夹取后血量之和 |
| `ids` | `std::vector<int>` | 升序、不重复 | 首次合法记录的编号 |

两条必须成立的守恒式（规范 6）：

```
valid + duplicate + invalid == frames.size()
valid == ids.size()
```

把这两条写成自测断言，能一次抓住绝大多数分类错误。

## 3 规范逐条拆解

| 题面规范 | 翻译成代码动作 | 最容易踩的坑 |
| --- | --- | --- |
| 1 直接读字段 | 不做文本解析 | 误以为要 `istringstream`（那是 Q4） |
| 2 `id∈[0,9999]` 且 `hp∈[-1000,1000]` | 先判范围，非法直接 `invalid` 并 `continue` | 用 id 访问标记表前没判 id 合法性 → 越界 |
| 3 完整合法后才判重复 | `seen[id]` 为真才计 `duplicate` | 先判重复 → 非法记录被误计重复 |
| 4 首次合法：夹血、累加、存编号 | 三件事一起做，`seen[id]=true` | 用原始 hp 累加；夹到 [0,100] 写成别的范围 |
| 5 `ids` 升序 | 最后 `std::sort` 或按编号扫描标记表 | 按到达顺序返回 |
| 6 守恒、空输入、调用独立 | 局部 `Summary`；两条守恒式 | 用 `static`；空输入没初始化 |
| 7 不改输入 | `const&` | 原地排序 `frames` |

## 4 核心一：分类顺序为什么不能换

这是本题最容易丢分的地方。看两个对比例子：

| 输入 | 正确分类 | 错误分类（先判重复） |
| --- | --- | --- |
| `{{1,20},{1,-1001}}` | 首次合法 + 非法 → `valid=1, invalid=1` | 编号 1 已见 → `duplicate=1` ❌ |
| `{{1,-1001},{1,30}}` | 非法 + 首次合法 → `valid=1, invalid=1, total_hp=30` | 非法记录占编号 → 后一条变重复 ❌ |

正确结构是**两道门**：

```cpp
for (const Telemetry& frame : frames) {
    // 第一道门：范围验证。非法者不接触标记表
    if (frame.id < 0 || frame.id > 9999 ||
        frame.hp < -1000 || frame.hp > 1000) {
        ++out.invalid;
        continue;
    }
    // 第二道门：只有合法记录才查重
    if (seen[frame.id]) {
        ++out.duplicate;
        continue;
    }
    // 通过两道门：首次合法
    seen[frame.id] = true;
    ++out.valid;
    // 夹血、累加、存编号
}
```

**先判范围还有安全意义**：`seen` 标记表大小是 10000，只有确认 `id ∈ [0,9999]` 后才能用它做下标。若先判重复，`seen[-1]` 或 `seen[10000]` 就是越界访问，未定义行为。

### 用 `std::vector<bool>` 做标记表

编号上限 9999 是固定的，所以开一个长度 10000 的布尔表即可，`O(1)` 查重：

```cpp
std::vector<bool> seen(10000, false);
```

用 `std::set<int>` 也能做，但查找是 `O(log k)`、还要额外动态内存；本题编号范围已知，位表更直接。（`vector<bool>` 是标准库的特化代理类型，当普通 bool 数组用即可。）

## 5 核心二：接收范围与夹取范围是两回事

题面有两套数字范围，混淆它们是常见错误：

| 环节 | 范围 | 用途 |
| --- | --- | --- |
| **接收验证** | `hp ∈ [-1000, 1000]` | 判断记录是否合法；超出即 `invalid` |
| **累计夹取** | `hp ∈ [0, 100]` | 合法记录的血量贡献值 |

```cpp
int hp = frame.hp;                 // 此时已知 hp 在 [-1000,1000]
if (hp < 0) hp = 0;
if (hp > 100) hp = 100;
out.total_hp += hp;                // 只累加夹取后的值
```

所以 `hp=200` 是**合法**记录，但只贡献 100；`hp=-5` 合法，贡献 0；`hp=-1001` 直接非法，不贡献也不占编号。题面样例1 的 `total_hp=100` 正是 `200→100` 加 `-5→0` 的结果。

### 为什么 `total_hp` 必须是 `long long`

最多 10000 个首次合法记录，每个最多贡献 100，总和上限 **10⁶**。`int` 上限 2.1×10⁹，其实放得下；但题面接口明确给的是 `long long`，照做即可，也留出余量。

## 6 编号排序

`ids` 要求升序，与到达顺序无关。两种做法：

| 做法 | 代码 | 复杂度 |
| --- | --- | --- |
| 先按到达顺序收集，末尾排序 | `std::sort(out.ids.begin(), out.ids.end());` | `O(k log k)`，本题 `k ≤ 10000` |
| 从 0 到 9999 扫描标记表 | `for (int i=0;i<10000;++i) if (seen[i]) ids.push_back(i);` | `O(10000)` 固定 |

参考实现用第一种，代码最短。两种结果完全一致。注意题面规范 7 禁止修改 `frames`，但 `out.ids` 是我们自己的结果容器，排序它没问题。

## 7 完整参考实现

```cpp
Summary summarize(const std::vector<Telemetry>& frames) {
    Summary out{0, 0, 0, 0, {}};
    std::vector<bool> seen(10000, false);

    for (const Telemetry& frame : frames) {
        // 第一道门：范围验证（非法记录不占编号）
        if (frame.id < 0 || frame.id > 9999 ||
            frame.hp < -1000 || frame.hp > 1000) {
            ++out.invalid;
            continue;
        }
        // 第二道门：查重
        if (seen[static_cast<std::size_t>(frame.id)]) {
            ++out.duplicate;
            continue;
        }
        // 首次合法：标记 + 统计 + 夹取 + 存编号
        seen[static_cast<std::size_t>(frame.id)] = true;
        ++out.valid;
        int hp = frame.hp;
        if (hp < 0) hp = 0;
        if (hp > 100) hp = 100;
        out.total_hp += hp;
        out.ids.push_back(frame.id);
    }

    std::sort(out.ids.begin(), out.ids.end());
    return out;
}
```

关键点：

- `Summary out{0,0,0,0,{}}` 一次性初始化全部字段，空输入自然返回全 0 与空 `ids`。
- 每条记录**恰好**落进三个分支之一，两条守恒式自动成立。
- `seen` 是局部表，每次调用重建，保证调用独立。
- 没有读 stdin、没有抛异常、没有调试输出。

## 10 边界实测

参考实现在本机 `g++ 16.2.0 -std=c++17 -Wall -Wextra -Wconversion` 下零警告，`PUBLIC 2/2`，`q8_extra.cpp` **全过**。摘录关键项：

| 输入 | 期望 `(valid,dup,inv,total_hp,ids)` | 考查点 |
| --- | --- | --- |
| `{{2,200},{1,-5},{2,10},{-1,30}}` | `(2,1,1,100,{1,2})` | 题面样例；200 夹到 100，-5 夹到 0 |
| `{{1,-1001},{1,30},{1,1001}}` | `(1,0,2,30,{1})` | 非法不占编号；已见编号的非法仍计非法 |
| `{{1,20},{1,-1001}}` | `(1,0,1,20,{1})` | 先验合法再判重复 |
| `{{2,5},{1,9}}` | `(2,0,0,14,{1,2})` | 编号排序非到达顺序 |
| `{}` | `(0,0,0,0,{})` | 空批次 |
| `{{0,50}}` / `{{9999,50}}` | 各 `(1,0,0,50,{id})` | id 两端点合法 |
| `{{-1,50}}` / `{{10000,50}}` | 各 `(0,0,1,0,{})` | id 越界 |
| `{{1,-1000}}` / `{{1,1000}}` | `(1,0,0,0,{1})` / `(1,0,0,100,{1})` | hp 端点合法并夹取 |
| `{{1,-1001}}` / `{{1,1001}}` | 各 `(0,0,1,0,{})` | hp 越界 |
| `{{1,10},{1,90}}` | `(1,1,0,10,{1})` | 重复不累加 |
| `{{9,10},{3,20},{7,30}}` | `(3,0,0,60,{3,7,9})` | 乱序编号 |
| 20000 条（10000 首次 + 10000 重复） | `(10000,10000,0,500000,...)` | 规模上限与守恒 |

另外做了 **3000 组随机差分**：按题面规范用 Python 独立重写分类逻辑，记录含非法 id、非法 hp、合法负数、重复编号，结果 **0 处不一致**。

## 11 缺陷定位与修复（README 素材）

本参考实现一次通过，没有代码缺陷。但有一个值得写进 README 的**测试设计教训**：

| 阶段 | 观察 | 结论 |
| --- | --- | --- |
| 设计自测时 | 只测"合法记录"无法区分"先验证再判重"和"先判重再验证"——两种实现对 `{{2,200},{1,-5},{2,10},{-1,30}}` 结果相同 | 必须构造 `{{1,20},{1,-1001}}` 这类"已见编号 + 非法血量"用例，才能让顺序错误暴露 |
| 加上守恒断言后 | `valid + duplicate + invalid == frames.size()` 与 `valid == ids.size()` 能一次抓住漏分类、重复计数 | 把规范里的恒等式直接写成断言，比逐字段比对更省事 |

这段说明：**测试覆盖要针对规范的区分点，而不是只跑样例**。样例1 里非法记录的编号 `-1` 从未出现过，所以分类顺序错了也看不出来；只有让"非法记录恰好使用已见编号"，才能验证规范 3 的优先级。

## 12 常见错误对照表

| 错误写法 | 后果 | 正确做法 |
| --- | --- | --- |
| 先判 `seen[id]` 再验范围 | 非法记录被计重复；`seen[-1]` 越界 | 先验范围，再查重 |
| 非法记录也 `seen[id]=true` | 后补的合法记录被误判重复 | 非法分支直接 `continue` |
| 用原始 hp 累加 | `hp=200` 贡献 200 而非 100 | 夹到 [0,100] 再累加 |
| 把 [-1000,1000] 当夹取范围 | 负数贡献负值 | 接收范围与夹取范围分开 |
| `int total_hp` | 接口不符（虽本题装得下） | 用 `long long` |
| 按到达顺序返回 ids | 违反规范 5 | `std::sort` 或按编号扫描 |
| 用 `static` 标记表 | 调用间串味 | 局部 `vector<bool>` |
| 漏掉某条记录的分类 | 守恒式破坏 | 三分支互斥且穷尽 |
| 对 `frames` 排序 | 违反规范 7 | 只排序 `out.ids` |

## 13 复杂度

- **时间**：`O(n + k log k)`，`n = frames.size() ≤ 20000`，`k = valid ≤ 10000`。分类阶段每条记录 `O(1)`，末尾排序 `ids`。
- **空间**：`O(10000)` 标记表 + `O(k)` 结果 `ids`（返回值不计入额外空间）。
- **数值**：`total_hp ≤ 10000 × 100 = 10⁶`，`long long` 余量充足。
